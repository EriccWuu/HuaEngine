## 3. 技术约束

- 当前引擎主体是 C++17 / CMake / OpenGL / GLFW / GLAD / EnTT / ImGui。
- 现有运行链路围绕 `Application -> LayerStack -> Scene -> RenderSystem` 组织，且 Editor 目前是重要宿主。
- 现有持久化主通路只有 JSON backend 稳定接入。
- 当前目标是先建立可持续演进的 headless/AI-friendly 架构，不做具体命令清单和任务拆解。

## 8. 现有代码库分析

### 8.1 相关模块

- Core Runtime: 当前所有宿主统一入口，适合作为 headless 宿主的基础设施层
- Scene / ECS: 场景、实体、系统更新的核心运行域
- Serialization / Reflection: 当前最接近无 GUI 可操作对象模型的稳定基础
- Editor Workbench: 当前 GUI 宿主，后续应改为应用服务层消费者
- Rendering: 现阶段不是 headless 化的第一目标，但后续应作为接入同一操作面的消费者

### 8.2 可复用组件

- `Application` 与统一启动链
- `SerializationManager + JsonSerializationBackend`
- `Scene` / `EntityManager` / `System`
- `LogSink` 与 Console 共享日志缓冲

### 8.3 需要新增的规划对象

- Headless/CLI Host
- Application Service Layer
- Unified Result Model
- Operation Registry / Capability Facade
