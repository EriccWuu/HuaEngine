## 3. 技术约束

- 约束 1: 当前技术底座固定在 C++17 / CMake / OpenGL / GLFW / GLAD / EnTT / ImGui
- 约束 2: 现有运行主链已围绕 `Application -> Scene -> RenderSystem -> RendererAPI(OpenGL)` 形成雏形，规划必须沿当前实现演进而不是推倒重来
- 约束 3: 当前不追求重型工具链，Editor 与 Sandbox 仅作为验证面和演示面
- 约束 4: 现有序列化真正稳定接入的只有 JSON backend，规划不能假定多格式后端已成熟

## 8. 现有代码库分析

### 8.1 相关模块

- Core / Runtime: 负责 `Application`、Window、Layer、Event、Log 与 ImGui 生命周期
- ECS / Scene: 负责 Entity、Scene、System 更新和未来脚本宿主
- Serialization / Reflection: 负责 JSON backend、默认 `Serializer<T>` 与资源/场景自定义特化
- Rendering: 当前主路径基于 `RenderSystem -> Renderer -> RenderCommand -> OpenGLRendererAPI`
- Editor / Sandbox: 当前用于工作台验证与演示

### 8.2 可复用组件

- `SerializationManager + JsonSerializationBackend`: 可继续作为基础持久化通道
- `Scene + EntityManager + System`: 可扩展成统一场景运行框架
- `MaterialSerializer` / `Mesh` 特化: 可作为未来资产系统的现有资源落点
- `EditorLayer` / `SceneHierarchyPanel`: 可继续承担基础能力验证 UI
