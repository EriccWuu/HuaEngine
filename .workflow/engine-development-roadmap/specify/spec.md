## 1. 概述

为 HuaEngine 制定一份面向当前到中期开发窗口的上层开发 roadmap，用来指导能力建设顺序、阶段边界和资源投入方向，优先确保基础引擎能力可用，再进入渲染能力强化阶段。

**目标用户**: 引擎维护者、引擎模块开发者、未来使用引擎做游戏或演示的开发者

**成功指标**:
- roadmap 明确至少 4 个连续阶段，并且每个阶段都有阶段目标、完成条件、进入下一阶段的条件
- roadmap 明确“基础能力优先，渲染深化后置”的顺序，避免范围蔓延
- roadmap 能让开发者判断当前工作属于哪个阶段、哪些内容暂缓、何时可以进入下一阶段

### 1.1 判定口径

本规范只定义 roadmap 的上层要求，不定义技术实现方案。

这里的“可观察完成标准”是指团队可以通过文档、运行结果、编辑器或 sandbox 演示、能力是否可被实际使用等方式直接判断的阶段结果；它不要求说明类设计、接口细节、数据结构或具体算法。

这里的“进入下一阶段条件”是指开始将主资源投入下一阶段前，当前阶段必须已经满足的上层 gate，而不是底层实现细节清单。

## 2. 问题陈述

### 2.1 当前状态
HuaEngine 已经具备多个模块原型和基本运行骨架，但缺少一份上层 roadmap 来统一阶段目标、优先级和范围边界。当前能力分布在 Core、ECS/Scene、Rendering、Serialization、Reflection、Editor、Sandbox 等模块中，存在“功能雏形已出现，但何时算阶段完成、接下来先做什么”不够清晰的问题。

### 2.2 痛点
- 当前模块能力分散，缺少统一阶段目标，容易在多个方向上同时推进而失焦
- 基础引擎能力、工具需求与渲染深化之间的先后关系未被正式固化
- 资产管理、序列化/反序列化、脚本继承这些由用户明确指定的基础能力主题，尚未被提升到上层优先级承诺
- 没有显式的范围外说明，容易把工具链、编辑器完善度等内容过早拉入当前阶段

### 2.3 期望结果
形成一份能指导接下来多个阶段开发的 roadmap：先把引擎作为“可持续扩展的基础系统”立住，再把重心转向渲染能力提升，并且整个过程对每一阶段的目标、边界、完成标志和进入下一阶段的条件都有明确说明。

- [ ] AC-3.4: roadmap 对未来渲染增强阶段与前置阶段之间的衔接关系有清晰说明

**备注**: 这是整个 roadmap 的长期方向约束。

```
作为引擎维护者，
我想要 roadmap 明确当前不追求非常完善的工具链，

**验收标准**:
- [ ] AC-4.1: roadmap 明确说明当前阶段允许保留轻量 editor / sandbox 验证方式
- [ ] AC-4.2: roadmap 明确说明完整工具链、复杂工作流和重型生产力工具不属于当前优先范围
- [ ] AC-4.3: roadmap 说明工具能力在当前阶段的目标是“支撑验证核心能力”，而不是“独立成为主目标”
- [ ] AC-4.4: roadmap 不把工具链完善度作为基础阶段完成前置条件

**备注**: 此故事用于控制范围，而不是否定未来工具链建设。

### US-5: 为渲染强化阶段建立进入条件

**优先级**: Should

```
作为未来使用引擎做游戏或演示的开发者，
我想要 roadmap 明确渲染能力会在基础能力稳定后成为重点阶段，

**验收标准**:
- [ ] AC-5.1: roadmap 把渲染增强定义为基础能力之后的重点阶段，而不是与基础能力并列抢资源
- [ ] AC-5.2: roadmap 明确描述进入渲染强化阶段前需要先具备的基础能力状态
- [ ] AC-5.3: roadmap 说明渲染强化阶段的目标是提升渲染能力边界，而不是模糊表述为“继续优化引擎”
- [ ] AC-5.4: roadmap 使读者能清楚判断当前工作更接近基础能力建设、渲染强化准备还是渲染强化本身

**备注**: 这里定义的是阶段关系和用户预期，不展开渲染方案细节。
